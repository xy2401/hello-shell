# Oils for Unix 常见坑位

> 本页结论：在使用 Oils 时，最容易踩坑的地方在于“OSH 兼容模式”与“YSH 现代模式”之间的切换与上下文感知。

## 1. OSH 与 YSH 混用的上下文

Oils 引擎会根据扩展名或特定的头部声明（Pragma）来决定当前使用哪个解析器。
**坑位**：在一个以 OSH 模式运行的脚本中，直接写入 YSH 专有的赋值语法（如 `var x = 1`）会导致解析错误；反之亦然。

## 2. 严格模式的阵痛

Oils（尤其是 YSH）默认开启了类似 Bash 中 `set -euo pipefail` 的严格模式，并且修复了 Bash 中一些边缘的“静默失败”漏洞。
**坑位**：将一个年久失修、写得不规范的 Bash 脚本喂给 Oils，你可能会立刻收到满屏的崩溃报错。这并不是 Oils 的兼容性不好，而是它拒绝“带病运行”，暴露了你脚本里原本就存在的未初始化变量或隐藏失败。
